## Exact Blocker

The accepted live runner cannot safely execute the approved six-worker pilot.
It consumes the single approval `run_id` before every spawn, although the
approval model binds all six workers to that same run. The first permitted
launch would therefore make every remaining exact binding fail closed as
already consumed.

## Summary

The failure was detected before approval materialization or process launch and
is contained to the runner's one-shot consumption cardinality.

## What Was Attempted

- All six registered detached worktrees are clean and pinned to reviewed
  commit `cad70bf7858f3eace5d68c7683feb4cde6c0901b`.
- The installed OpenCode PowerShell wrapper matches the reviewed provenance
  digest.
- `scripts/local_opencode_executor.py` denies any request whose `run_id` is
  already in `consumed_run_ids`, then adds that ID before the spawn boundary.
- The accepted preflight and approval draft provide one shared run ID for six
  bindings.

## Scope / Risk Impact

No launch-time approval was materialized or consumed. No OpenCode, PowerShell,
Popen, provider configuration, credential, network, Git worktree mutation,
merge, push, cleanup, prompt, source body, or raw process output was used.

## Recommended Next Action

Open and independently review a narrowly scoped correction that preserves a
single one-shot pilot approval while recording per-binding launch consumption
for the exact six bound identities. It must retain no retry/fallback behavior,
matching stop handling, and privacy-bounded evidence. A new current approval
must then be materialized; this attempt is not reusable.
