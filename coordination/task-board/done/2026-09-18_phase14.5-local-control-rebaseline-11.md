# Task Packet

## Objective

Rebase the Phase H acceptance model to the operator-approved L1 local
controlled-collaboration mode, while preserving L2 platform isolation as an
optional later hardening path.

## Context

Read the existing Phase H card and protocol, accepted adapter/provisioner
reviews, platform-enforcement incident, and controlled-orchestration
architecture. This is a safety-model change, not an implementation task.

## Constraints

No runtime, connector, network, credential, Git worktree, merge, push, or
cleanup action is permitted. Do not weaken the existing critical-action
approval gate. Do not describe L1 as enforced isolation, a sandbox, or network
denial.

## Implementation Notes

Use the existing evidence vocabulary wherever possible. The smallest correct
change is a terminology and acceptance rebaseline plus one deterministic
contract test; do not introduce a new service, adapter, profile, or platform
dependency.

## Token And Resource Impact

No agent/runtime is started. L1 changes only the future pilot's safety claim
and test contract; the existing one-shot approval remains the disable path.

## Validation Steps

Run the new/affected contract tests, the Phase B.1--H fixture suite,
`scripts/orchestrate.py validate`, and `git diff --check`.

## Escalation Rules

Stop and file an incident if a document requires a claim of platform-enforced
filesystem or network isolation, or if L1 would weaken credentials, merge,
push, cleanup, or one-shot runtime approval controls.
