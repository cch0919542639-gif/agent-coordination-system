# Task Packet

## Objective

Create the fail-closed core required to answer one reviewed OpenCode Server
permission request per exact Phase H binding. It is preparation only.

## Context

The user authorized the loopback API-controller route after Desktop UI control
was unavailable. OpenCode exposes a session permission-response API; the actual
loopback transport and any runtime remain separate, freshly approved boundaries.

## Constraints

The controller must not create a server, make HTTP calls, read configuration,
access credentials, or materialize a launch. It must use an injected reply
callable, bind to opaque session and permission IDs, compare a supplied
resource digest, issue only `once` with `remember: false`, and consume the
permission identity before the callback.

## Implementation Notes

Use only the injected reply callable. Keep transport, server lifecycle,
credential handling, and pending-request retrieval out of this task.

## Validation Steps

Run the focused test module and coordination validation. Submit for independent
review before any adapter or live server task is created.

## Escalation Rules

Stop on an API schema mismatch, a need to expose raw resource data, or any need
to start a server, contact a provider, or access a credential.
