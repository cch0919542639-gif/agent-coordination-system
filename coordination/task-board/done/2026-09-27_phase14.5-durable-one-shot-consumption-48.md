# Task Packet

## Objective

Replace caller-owned in-memory-only consumption sets with a small durable
one-shot ledger that can fence approvals and exact permission requests across
process restarts.

## Context

The current executor consumes approval and binding identities in a Python set;
the Task 44 permission core similarly consumes permission identities in a set.
Both are replayable after process restart unless the caller provides durable
state.

## Implementation Notes

Prefer a caller-supplied trusted local state directory and exclusive file
creation for single-winner claims. Reject symlink/junction components and
persist only opaque identity digests. This packet supplies storage mechanics;
Task 49 wires successful claims before side effects.

## Constraints

Implement storage mechanics only. No launch, HTTP, credentials, or changes to
global permissions. Store only opaque IDs and digests. Atomic exclusive file
creation is the baseline; concurrent callers must have one winner.

## Validation Steps

Run the new focused test module and coordination validation. Submit for
independent review before wiring into runtime code.

## Escalation Rules

Stop if a safe location cannot be provided by the caller or durable storage
would require credential material or a new service.
