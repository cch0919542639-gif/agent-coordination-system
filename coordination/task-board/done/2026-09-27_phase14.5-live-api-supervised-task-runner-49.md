# Task Packet

## Objective

Connect task payload delivery, exact one-time permission API handling, durable
approval consumption, and real-time supervision into a reviewable runner.

## Context

Tasks 44 and 45 are accepted mock-transport components, and Task 46 accepted a
schema-only OpenCode 1.18.32 diagnostic. None proves task delivery, runtime
success, durable current authority, or continuous supervision.

## Constraints

This task is implementation and mock verification only. Do not start a server,
runtime, worker, or model request. Do not reuse Task 43 or expired run/window
evidence. Do not inspect provider configuration or credentials. Never auto-
approve beyond the exact current task/run/binding or persist a remembered rule.

## Implementation Notes

Use the v1.18.32 session API mapping: create with `POST /session?directory=...`,
verify the returned session directory, deliver with `POST
/session/{sessionID}/prompt_async`, observe the exact session through injected
status/heartbeat callbacks, and stop with `POST /session/{sessionID}/abort`.
Reuse approved binding and lease metadata. Keep process, transport, clock, and
state-store dependencies injectable; use monotonic deadlines for active
supervision and persist only privacy-bounded evidence. Tests must not invoke
these request builders through a live transport.

## Validation Steps

Run focused tests, compile affected modules, coordination validation, and
`git diff --check`. Obtain independent review before presenting any live pilot
for separate user authorization.

## Escalation Rules

Stop if the public API contract drifts, the exact assigned task cannot be
bounded, current authority cannot be durably consumed, or supervision cannot
reliably terminate the exact child.
