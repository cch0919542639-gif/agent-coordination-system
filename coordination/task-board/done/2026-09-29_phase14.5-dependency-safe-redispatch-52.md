# Task Packet

## Objective

Complete the repository-side loop after a worker reports: protect direct and
suggested dispatch with dependency checks, and allow one explicit next-task
assignment as part of an accepted human review command.

## Context

Task 49 supplies a task-bound supervised API runner; Task 51 supplies local
HTTP callback wiring after its review. Neither automatically accepts task
reports. The task board remains authoritative, and all reviews are human
decisions. Five agent machines are being prepared by the user separately.

## Constraints

`--continue-after-accept` is opt-in and is only valid with `--decision
accepted`; require an explicit `--continue-owner`. Accept and record the review
first, then dispatch no more than one currently `ready` task whose dependency
cards are all in `done/`. Use deterministic board order. Do not steal tasks
from another owner. No available candidate is a successful accepted review
with a clear continuation-paused result.

## Implementation Notes

Reuse `wave_planner.py` for dependency eligibility. Direct dispatch must use
the same eligibility rule as `orchestrate next` and continuation. Keep task
review state changes separate from worker execution; this command only updates
assignment metadata and prints the normal dispatch message.

## Validation Steps

Run the focused new regressions, relevant existing dispatch/wave tests,
coordination validation, compilation of changed scripts, and `git diff --check`.
Do not run an OpenCode process, API request, or live task.

## Escalation Rules

Stop if selecting a next owner requires guessing a worker identity, if an
accepted review cannot be durably recorded before dispatch, or if safe
dependency evidence cannot be distinguished from missing/malformed cards.
