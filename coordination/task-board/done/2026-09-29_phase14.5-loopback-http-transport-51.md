# Task Packet

## Objective

Replace the transport callbacks left injected by Task 49 with a concrete,
privacy-bounded local OpenCode HTTP adapter that is callable by that runner.

## Context

Tasks 46–49 established the v1.18.32 route shapes, bounded task prompt, exact
one-shot permission path, durable consumption, and task/session supervision.
Task 49 intentionally left all network operations injected. The user allowed
one CLI connectivity smoke only; that smoke has already completed and must not
be repeated. This packet is transport implementation and fake verification
only, not authority to run a task through OpenCode.

## Constraints

Use Python standard-library HTTP only, and require an exact plain-HTTP
`127.0.0.1:<port>` origin. Do not read local OpenCode configuration or
credentials. Do not launch a server or process, connect to a server, send a
prompt, fetch a live permission queue, or reply to a live permission. Never
follow redirects or retry side-effecting requests. Do not persist response
bodies, request prompts, or transcript material. Preserve Task 49's separate
current approval and durable one-shot gates; this transport does not create,
validate, or consume authority.

## Implementation Notes

Bind callbacks to one origin. Restrict request methods/routes to the exact
session create, async prompt, session/status, exact-session read/abort,
permission list, and modern permission-reply endpoints already used by the
accepted adapters. Heartbeat may confirm only the exact session ID and
directory. Session-status idle is ambiguous before activity: report completion
only after this transport observed that session busy/retry and later idle;
unknown or malformed status is unavailable. A missed busy sample must fail
closed rather than infer completion. Keep the HTTP connection injectable so
tests perform no network I/O.

## Validation Steps

Run only the new focused fake-transport module, module compilation,
coordination validation, and `git diff --check`. Do not run an OpenCode command,
local server, provider request, permission response, or six-agent pilot.

## Escalation Rules

Stop if the installed v1.18.32 response shape differs from the accepted route
contracts, if completion cannot be established without treating an initial
idle state as success, or if transport would need authentication/configuration
inspection or a non-loopback destination.
