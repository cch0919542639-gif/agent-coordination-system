## Task Packet

### Objective

Remove the worker's manual report-file and submit-command steps from the local
supervised loop while preserving a human review decision before any continuation.

### Context

Tasks 49, 51, and 52 provide the supervised task runner, fake-tested loopback
transport, and accepted-review continuation. Idle supervision currently returns
without reading a final response or submitting delivery evidence. The user
authorized completing local automation; five worker machines remain theirs to
prepare. The earlier single connectivity smoke is complete and must not repeat.

### Constraints

Use only the existing standard-library transport and injected fake connections
for verification. Treat model output as untrusted worker claims. Bound all
fields, redact by rejection when secret-like content is detected, and never
persist transcripts. Keep manual review, explicit continuation, current
one-shot approval, no-launch, and no-commit/push boundaries.

### Implementation Notes

Use one exact-session message callback and a strict JSON manifest in the final
assistant message. Create a report that identifies worker claims and asks the
reviewer to inspect actual repository evidence. Reuse the submit lifecycle
logic programmatically rather than duplicating its state and owner checks.

### Validation Steps

Run focused fake-only tests for the changed runner, transport, callback, and
submission lifecycle, plus module compilation, coordination validation, and
`git diff --check`. Do not launch OpenCode, a server, or a model/API request.

### Escalation Rules

Do not submit if the final-message shape or session binding is unclear, if the
task card changed while the worker ran, or if report creation and task-state
transition cannot be made safely. Keep the report in review only for human
acceptance.
