## Task Packet

### Objective

Remove the worker's final report-writing step as well as the separate submit
command. Build the report from controller-observed changes for the exact
supervised run, then automatically submit it for human review.

### Context

Task 53 automated creation of the report file and submission, but still asked
the worker for a structured final manifest. That manifest is still worker
authored. The controller already knows the pinned worktree directory, task
scope, run identity, and exact session completion point.

### Constraints

Keep file capture scoped to the task card's allowed paths, bounded, read-only,
and in memory. Never persist file contents, response text, hashes, or a raw
snapshot. Do not infer that tests passed when the controller did not observe
their results. Keep human review and optional continuation unchanged. No live
OpenCode, model, provider, commit, push, merge, or worker launch.

### Implementation Notes

Take the baseline after worktree validation but before any worker session starts.
After `supervise_session` returns completed, take the second snapshot and
classify additions, modifications, and deletions by comparing per-file hashes.
The delivery callback should create a concise report from these facts and the
bound task/run/session metadata, then use the shared strict submission
lifecycle.

### Validation Steps

Use fake directories and fake transports only. Verify paths outside allowed
scope never appear, symlinks are not traversed, resource limits fail closed,
the final model response is not required or persisted, and state/owner changes
during collection prevent report creation. Run the focused Task 49/51/52/53/54
regression suite, module compilation, coordination validation, and
`git diff --check`.

### Escalation Rules

If the allowed scope is malformed or the bounded snapshot cannot be captured
reliably, do not start the worker session or submit an incomplete report. Keep
the task in progress and report the specific controller-side limitation.
