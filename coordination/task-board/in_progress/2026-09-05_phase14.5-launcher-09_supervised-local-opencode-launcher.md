# Task Packet

## Objective

Implement the smallest launcher that can make one already-admitted external
OpenCode worker actually begin a single assigned task and report one bounded
terminal outcome. This closes the gap between durable handoff creation and an
external runtime doing work.

## Context

Read the controlled orchestration architecture, the supervised one-shot launch
design, the accepted connector-grant/admission delivery, and the B0 review
evidence. Munder Difflin is a reference for mailbox and idle-wake mechanics,
not for its GOD autonomy, PTY control plane, or approval model.

## Constraints

- A real start is permitted only after this implementation has independent
  review and the operator records approval for the exact manifest and grant.
- The launcher must use an allowlisted executable identity and immutable argv
  structure; task text and environment values must never become commands.
- It must create no task-card lifecycle transition, Git mutation, push, merge,
  credential access, broad network grant, automatic retry, or worker-to-worker
  dispatch.
- Timeout, non-zero exit, missing acknowledgement, and stop request are
  terminal outcomes with one safe incident record.

## Implementation Notes

Keep manifest/grant validation pure and fake-clock testable. Isolate process
creation behind one small adapter that accepts only a preconstructed argv array
from the validated manifest. Default to dry-run; the supervised path must not
be callable without an exact approval reference.

## Validation Steps

Run focused fake-process tests for every denial path, one-process-only success
path, timeout, non-zero exit, and audit redaction. Run coordination validation
and `git diff --check`. The real pilot is a separate operator-approved step.

## Escalation Rules

Stop if full Windows sandboxing, a credential store, new persistent service,
or a second runtime is required. Record the enforcement gap rather than
claiming the supervised launcher is a full security sandbox.
