# Task Packet

## Objective

Build the smallest reviewed bootstrap bridge needed for a manually started,
pre-approved OpenCode worker to receive one bounded task handoff. This bridge
does not launch or control OpenCode; it only validates and materializes the
operator-approved, one-shot delivery artifact.

## Context

Read `docs/architecture/controlled-orchestration-architecture.md`,
`docs/operations/phase14.5-supervised-launch-design.md`, the accepted runtime
preflight and Phase A evidence, and the task map. The candidate runtime binding
is OpenCode with worker ID `external-agent-platform-33`; availability and
approval must be rechecked by the operator before any manual use.

## Constraints

- The operator, not this task, starts the external runtime.
- Do not call a process API, shell, OpenCode CLI, network service, credential
  store, or Git command; do not create a worktree or modify task-card state.
- Do not place credentials, provider identifiers, prompts, source bodies, raw
  logs, task text, or absolute paths in status, audit, or delivery records.
- Treat a missing, expired, altered, duplicated, or mismatched approval as a
  terminal denial. Do not provide fallback delivery or automatic retry.

## Implementation Notes

Use deterministic local functions and a fake clock. The handoff must contain
only an allowlisted task-card projection, protocol references, dependency
evidence references, project-relative paths, schema version, content digest,
size limit, sensitivity label, expiry, and an idempotency key. It is not a
connector grant and does not authorize a runtime launch.

## Validation Steps

Run focused tests for valid one-shot preparation, expiry, altered/mismatched
approval, duplicate/replay, unsafe path or payload rejection, and source-level
no-process/no-network coverage. Run coordination validation and `git diff
--check`.

## Escalation Rules

Stop and open an incident if a real runtime, credential, network transport,
worktree creation, task lifecycle mutation, or unapproved OpenCode invocation
is needed. A manual invocation requires a separate operator approval and is
outside this implementation task.
