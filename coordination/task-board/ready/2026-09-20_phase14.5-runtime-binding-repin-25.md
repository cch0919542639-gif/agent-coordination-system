# Task Packet

## Objective

Recover the fixed-runtime prerequisite identified by incident
`20260919-06_phase14.5-fresh-attested-pilot-runtime-unavailable` without
weakening the accepted one-shot launch boundary.

## Context

Task 24 supplied the independently checkable project wrapper and content pin.
Task 23 then stopped before admission because its wrapper's fixed
`opencode.exe` target was unavailable. The operator has now authorized a
separate runtime-binding re-pin and independent review, followed only after
acceptance by one new one-shot pilot. This packet itself has no launch
authority.

## Constraints

Use the smallest existing-boundary change. Read-only local executable identity
discovery is allowed solely to select and pin one available local OpenCode
runtime; it must not inspect provider configuration, credentials, child
output, or environment values, and it must not record the discovered raw path.
Do not create a configuration store, fallback resolver, runtime service, or
new dependency. Do not invoke the selected runtime or wrapper.

## Implementation Notes

Trace the executor and live-runner callers before editing. Reuse the existing
injected spawn seams and stdlib hashing/validation patterns. Preserve a
single exact mapping: any unavailable or changed binding is a pre-spawn denial,
not an alternate command or retry. Keep all externally visible results
privacy-bounded.

## Validation Steps

Run focused executor and live-runner tests with isolated basetemp, then
`py_compile`, coordination validation, and `git diff --check`. Include a
static scan or focused tests showing that all failure cases reach no injected
spawn/Popen call.

## Escalation Rules

Stop and open a redacted incident if one safe executable identity cannot be
bound without provider/configuration access, or if the change requires any
runtime invocation, credential access, network activity, or scope expansion.
Do not modify, revive, or consume Task 23.
