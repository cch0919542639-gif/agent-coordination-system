# Task Packet

## Objective

Create an evidence-backed architecture baseline for a six-agent controlled
orchestration plane, then define the bounded implementation sequence.

## Context

Read the root context kit, existing runtime-adapter and status-projector
evidence, and the checked-out ClawChat and ORCA research sources before
changing this task's allowed artifacts.

## Constraints

- Keep repository task cards as the lifecycle authority.
- Do not add a runtime, UI, network transport, credential store, dependency,
  or global shared resource in this architecture-only task.
- Do not copy external source code or include private source content.

## Implementation Notes

Describe only contracts, boundaries, and phased work for six or more agents.
Each later phase needs its own task packet and review before implementation.

## Validation Steps

Manually verify that the architecture preserves the existing task-card
authority, contains no sensitive data, and makes every critical action require
an explicit approval.

## Escalation Rules

Stop and open an incident if the design would require automatic high-risk
runtime launch, credential exposure, lifecycle mutation outside the task card,
or an unreviewed global resource.
