# Agent 操控面板（本機候選版）

## 直接模型

本機 Administrator 可以建立只處理文字的直接模型工作階段。選擇「直接模型」
後，從供應商選單選擇 OpenRouter、DeepSeek、Agnes AI 或自訂 OpenAI 相容
API，輸入該供應商的 API Key 與模型 ID，再按「連線 Agent」。DeepSeek 與
Agnes AI 提供範例模型；實際可用性和價格請向供應商確認。OpenRouter 可以
取得符合所選隱私模式的公開模型清單。清單不代表帳號有權使用或服務可用。

自訂供應商請填完整 HTTPS API 基底網址（例如 `https://example.com/v1`，
不含 `/chat/completions`）；網址不可含帳密、查詢或片段。金鑰和訊息會送往
該網址，請自行核對目的地。自訂模式需手動輸入模型 ID，不提供模型清單。

OpenRouter 預設為零資料保留，也可明確選擇一般模式。DeepSeek、Agnes AI
和自訂供應商使用各自的資料政策；主控台不保證或驗證其零資料保留，且
不會把 OpenRouter 專屬隱私參數送給它們。切換供應商會清除尚未送出的
金鑰及模型 ID；連線中的供應商與網址不可更換，需停止後重新連線。

金鑰使用密碼欄位，連線時經本機認證 HTTP 與程序管線傳入此次工作階段，
不寫入設定檔、命令列或版本庫。畫面在送出連線後清除金鑰；停止後重新
連線需要重新輸入。金鑰會在主控台與受控子程序的記憶體中短暫存在，並在
請求中傳給選擇的供應商；請使用安全的本機帳號及顯示環境。舊版的
`COORDINATION_OPENROUTER_API_KEY` 和 `COORDINATION_DIRECT_MODELS`
程序環境設定只適用 OpenRouter，仍可使用。

連線後可在模型 ID 欄位更換模型，按「套用模型」再送出文字。
傳送前確認內容及模型價格；設定付費模型可能產生費用。單次最多 50,000
字元，完整對話最多 100,000 字元；超過時請重新連線。切換模型會清除
此直接工作階段的對話歷史。回覆僅在登入工作階段中顯示，使用既有的
手動 Codex 回報按鈕才會送入指定對話。此模式不提供工具、讀檔或命令執行。
文字訊息綁定畫面顯示的工作階段、供應商、端點、模型與隱私模式；
套用模型和停止也綁定目前工作階段與供應商。若其他分頁切換，舊畫面的
操作會被拒絕，需重新整理頁面並確認。舊版頁面亦需重新整理。

零資料保留模式每次請求指定 OpenRouter 的 `zdr=true` 與 `data_collection=deny`；若沒有
符合條件的端點，服務會回報失敗，不會放寬條件或自動重試。一般模式不傳送
這兩項強制限制，不會修改供應商帳號隱私設定。模式綁定本次工作階段；需
停止後重新連線才能切換。這些條件依
供應商及 OpenRouter 的實際政策運作，並非本機離線推論。單次模型請求
最長等待 100 秒，逾時會停止該直接模型工作階段；主控台本身不會因此定時關閉。
停止、登出或關閉主控台會結束主控台擁有的程序，但已送出的
請求不保證能撤回，也可能已產生費用。HTTP 錯誤只顯示狀態，不顯示原始
供應商回應或金鑰；無文字或不完整的回覆不視為成功。可查閱
[OpenRouter 資料保護設定](https://openrouter.ai/docs/guides/get-started/sovereign-ai)。

此整合候選包含手動前景唯讀監控及 Agent 操控面板，尚未發布。一般有限時間
主控台保留既有角色與 Agent 操作；監控工作階段的帳號一律降為 Viewer，
無法操作 Agent 或派發任務。監控以獨立的前景指令啟動與停止，具體步驟見
[手動唯讀監控指南](console-monitor-guide.md)。它使用本機 OpenCode Desktop CLI
的 ACP 及 Hermes ACP，不包含 OpenBot 原始碼。面板只控制此登入工作階段
親自啟動的新 Agent；不接管桌面版既有對話、任務板工作者或其他程序。

## 多模型自動分工候選

Agent 操控頁可設定 2 至 4 個工作者，第一個必須是直接模型，負責將總任務拆分，
其餘可選直接模型、OpenCode 或受支援的 Hermes。工作者並行執行各自的子任務，
最後由第一個模型彙整；每項分工與
結果分開顯示。所有供應商都會收到總任務，各自收到分工內容，彙整模型
也會收到其他模型的結果（每項最多 4000 字，截短會標示）。這些請求
可能收費，且受各供應商資料政策約束。OpenRouter 可選零資料保留模式，
其他供應商不由主控台驗證該政策。金鑰不儲存，只供本次執行使用。

直接模型僅處理文字。選用原生 Agent 時，先按「確認來源專案」，核對 Git
根目錄及完整基底提交後勾選確認。系統會以該提交版本為基礎，為每個 Agent
建立個別工作樹；若版本已變更，須重新確認。原工作目錄未提交的變更
不會帶入。畫面顯示工作樹位置、基底版本、已追蹤及未忽略的變更、進度與
需要核准的操作。工作樹會保留，應由人檢查各項變更再決定如何整合；不會
自動合併、建立正式任務卡或驗收。

工作樹共用 Git 資料且不是作業系統沙盒，Agent 仍以目前使用者身分執行，
可能存取帳號可讀取的其他檔案及憑證。OpenCode 依既有授權執行工具，Hermes
保留個別操作核准。原生模型的回答會交給彙整模型，請勿在任務或結果放入
不適合傳給供應商的資料。停止會結束本次擁有的程序，但無法撤回已送出的請求。
此版本尚待獨立審查且尚未更新已安裝主控台。如無法確認程序已停止，系統會
暫停新團隊啟動；請先檢查程序再重新啟動主控台。

## 啟動與操作

1. 依 [本機控制台操作指南](web-console-guide.md) 或 [下載與初始化指南](console-download-guide.md)，準備**此候選工作樹**對應的本機控制台設定。啟動後以 Administrator 登入；預設新建的 Viewer 無操作權限。既有帳號不會被修改，亦不可假設另一個工作樹的綁定可直接重用。
2. 在 `Agent 操控` 選擇 OpenCode 或 Hermes，按「連線 Agent」。只有使用者操作時才建立 Agent 程序和新工作階段。
   控制台新建的 Hermes 工作階段使用精簡工具組：`read_file`、`write_file`、`patch`、`search_files`、`terminal`、`process`；其他工具及 MCP 不載入，並停用原生 lazy-deps 套件安裝與 Bitwarden helper 自動下載。這只套用到控制台新啟動的程序，不修改 Hermes 全域設定或已執行的工作階段；不保證攔截所有可能的安裝路徑。若原生 Hermes 更新後介面不相容、必要工具或套件缺失，可能無法啟動或使用相關功能，需檢查原生環境。
3. 「提供者／模型」取自該 Agent 回報的可用清單。選擇後按「套用模型」，並確認「目前模型」；選項可能隨原生登入、提供者及模型服務改變。提供者登入、金鑰和新增提供者仍須在 Agent 原生介面設定；控制台不提供憑證設定，也不主動讀取原生登入憑證。
   OpenCode 的控制台新連線預設使用 Big Pickle（`opencode/big-pickle`）；只透過該子程序的啟動設定套用，不修改原生全域設定。連線後仍可自行選擇其他可用模型。
   Hermes 的來源核對限於主模型提供者與端點，不驗證帳號身分；自動標題、對話壓縮等原生輔助功能可能依其設定將內容傳至其他提供者，這些輔助路徑不在核對範圍內。
4. 輸入指示並按「送出給 Agent」。這才會觸發外部模型請求，資料與費用取決於提供者。依使用者 2026-11-04 指示，OpenCode 工具命令直接執行，不逐項詢問；原生 ACP 若仍要求同意，由橋接器自動選擇 `allow_once`，不儲存永久授權。沒有可用單次允許選項時取消，不停留等待畫面操作。Hermes 偵測到的危險命令須逐次審批，面板提供單次允許或拒絕；背景程序輸入在此控制台中停用。危險命令偵測不是 OS 沙箱。回覆與工具進度仍顯示在面板，停止按鈕仍可用。
   依使用者選擇，Hermes 批准預覽的原始命令、路徑或檔案內容會傳到登入者的瀏覽器以便完整核對，可能含憑證；請確認顯示環境安全。若標題或內容超過畫面上限，面板只允許拒絕，請改用原生介面處理。Agent 回覆及操作進度同樣可能含敏感內容；系統不保證自動遮罩任意憑證，請勿分享畫面或輸出。
   新對話也可能依 Agent 原生設定保存在其本機資料目錄或提供者服務；面板登出只清除面板記憶體和畫面。
5. 要回報 Codex 時，核對完整的 Codex 對話 ID 與畫面上回覆，按「將目前回覆送入 Codex 佇列」並確認。若控制台由 Codex 啟動且繼承對話 ID，欄位會預填；仍須核對。回覆可能含敏感資料，會寫入所選 Codex 對話；只有 Administrator 能送出。入列不代表 Codex 已讀或已處理，不會自動啟動或恢復對話。程式將回覆標為外部不受信任資料，Codex 仍須自行辨識與審查。
6. 按「停止此 Agent」停止此面板擁有的程序樹；登出或控制台關閉亦會停止。重新連線會建立新工作階段。頁面不提供自動重啟、背景服務或開機自啟。

一般主控台及登入、Agent 工作階段預設持續運行，直到登出或手動停止；
關閉整個瀏覽器後可能需要重新登入。可選擇明確指定限時啟動。獨立的唯讀監控使用前景指令
持續同步及恢復子程序；它不開放 Agent 操控或正式任務生命週期操作。

直接執行設定只套用於控制台新啟動的 OpenCode 子程序，不修改全域權限或已存在的對話。重新整理頁面可看到模式說明；既有 Agent 需停止後重新連線才載入新設定。此手動面板尚無 OS 檔案／網路隔離，命令可存取啟動 Windows 帳號允許的範圍；不能當作隔離無人模式已完成。

## 已知現況與限制

- Hermes v0.23.1 的 ACP 使用共享 gateway 執行任務；此候選原先的精簡工具、路由與逐次審批防護只存在主控台啟動的程序，尚未證明能約束共享 gateway。當原本相鄰的 Python 啟動器不存在時，主控台會拒絕連線並顯示原因；不會自行連上共享 gateway 或放寬保護。Hermes Desktop 可用不代表此主控台整合已可用。
- 回報必須人工觸發且核對目標，系統先以不含對話歷史的中繼資料確認 ID，再送入指定對話佇列。同一登入工作階段內，同一 Agent 同一輪至同一目標不重送；回報結果不明或網路中斷時，應先檢查佇列，不要重新登入或重啟後盲目重送。此限制不是跨重啟的去重保證。回報只包含目前回覆，不包含操作紀錄或先前對話；也沒有從 Codex 自動派工的通道。
- 2026-11-17 依使用者要求，以主控台相同的 AgentSession 和 `opencode/big-pickle` 進行短任務：OpenCode 回覆指定標記；同一工作階段的後續任務亦正確回憶前一個測試代碼。這證明該次收發與後續對話可用，並不代表已將回覆送入 Codex 對話或保證未來服務配額。
- 此電腦曾缺少 Hermes ACP 依賴；2026-11-07 補齊後，原生 ACP 檢查與控制台連線通過，回報 88 個模型。Hermes 啟動可能超過 30 秒，控制台最多等待 90 秒；仍可手動停止。原工具組測試時本機預設 120B 與 Groq 20B 回報 413；精簡後兩者各以一次簡短請求回覆 OK。實際控制台亦曾以 OpenRouter 的 `nvidia/nemotron-3.5-lightning:free` 收到簡短回覆。模型清單或切換成功不保證提供者能處理其他請求。
- ACP 使用各 Agent 本身的登入及設定，不保證 CLI 的授權、提供者狀態或預設值與桌面應用完全相同；面板會顯示實際的 ACP 清單和錯誤。
- 測試包括模擬 ACP 對話、瀏覽器假資料，以及 OpenCode 真實握手、短任務和後續對話。Hermes 曾在隔離測試專案進行有限的真實推論與指定工具操作；已核對寫入內容和終端輸出，讀取操作只有開始事件，未獨立取得讀取結果。該 Hermes 測試發生於新版共享 gateway 變更之前；未驗證所有提供者或所有工具授權路徑。
