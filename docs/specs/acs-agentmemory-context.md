# ACS 記憶整合詞彙

本詞彙屬於規劃草案，未變更協作引擎的既有領域定義。

| 詞彙 | 定義 |
| --- | --- |
| 正式來源 | 專案 Git repository 內可定位到不可變提交的任務、決策、交接與驗證文件 |
| 核准文件 | 經指定 reviewer 或人類明確允許納入記憶、且來源與內容範圍已固定的文件；存在 GitHub 不等於已核准 |
| 經驗卡 | 從核准文件挑出的有來源、適用版本與現行狀態的簡短技術經驗 |
| 記憶副本 | 由正式來源衍生、可重建、可能過時的查詢輔助資料，不具有指派或核准權限 |
| 來源版本 | 正式來源的 repository、完整 commit SHA、文件路徑及文件內容雜湊所共同指向的版本 |
| 匯入批次 | 人工核准的一組固定經驗卡及其來源版本 |
| 匯入收據 | 可證明某批次的核准內容與記憶服務紀錄對應關係的紀錄；不包含帳密 |
| 取代 | 新經驗明確指出哪個舊經驗不再適用；舊來源歷史保留 |
| 撤回 | 某經驗不再應被提供作為建議；與刪除正式歷史不同 |
| 召回 | 根據使用者問題找出相關記憶與來源候選；回覆前仍須核對正式來源 |
| 交接 | 下一個執行者取得正確程式版本、正式任務與必要經驗後接續工作 |
| 整合驗收 | 以來源正確性、版本新舊、範圍隔離及失敗可恢復性判定整合是否可用；不等同容器啟動成功 |
